## Distribution boundary — what this pack does and does not redistribute

This repository's release assets (the installer pack zip, and the Electron-built DMG/EXE) contain
**only the FMG-authored integration layer and the Electron shell**. They do **not** redistribute
upstream binaries:

- **Hermes Agent, Hermes WebUI, and Paperclip are installed from source at first run**, cloned from
  the pinned repositories/commits recorded in `installer.manifest.json`
  (`mode: "local-fmg-source-install"` for Paperclip). Their code never ships inside this pack's
  release assets.
- **Transitive dependencies are fetched by the user's own package manager at install time.** In
  particular, Paperclip depends on `embedded-postgres`, whose payload is a PostgreSQL distribution
  plus third-party shared libraries (OpenSSL, ICU, and others) under their own licenses. Because
  this pack does not redistribute that payload, those licenses govern the user's download from the
  package registry, not this repository's release assets.
- **Electron builds embed Chromium/Electron license files** generated by electron-builder inside
  the DMG/EXE (e.g. `LICENSES.chromium.html`). Those remain in the built artifacts and must not be
  stripped.

**Obligation trigger**: if a future version of this installer ever bundles upstream artifacts into
its release assets — Paperclip's `node_modules`, an embedded-postgres payload, prebuilt Hermes
binaries, or a prebuilt WebUI — the third-party notices for everything inside that payload
(PostgreSQL license, OpenSSL, ICU, and the rest) must be added to this file and shipped with the
artifact **in the same release**. Do not bundle first and attribute later.

## Secret and credential policy

This repository and its release assets must not contain:

- API keys or model provider credentials
- Telegram bot tokens
- Paperclip tokens or private company secrets
- Codex OAuth/device credentials
- OpenCrab MCP endpoint keys
- Private keys, certificates, or signing credentials

Users configure credentials locally through Hermes setup, local `.env` files, OAuth/device login, or the relevant service UI.
